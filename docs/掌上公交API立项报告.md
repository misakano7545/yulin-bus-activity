## 1. 结论摘要

| 问题 | 结论 |
|---|---|
| 接口能不能用 | **能用**，且是本项目见过的最省事的一个数据面 |
| 有没有签名 / 加密 / 登录 | **没有**。表单明文请求，明文 JSON 响应，无 token、无 cookie、无时间戳签名 |
| 城市凭据难不难拿 | **不难，而且不用拿**。用 `CITYCODE`（行政区划码）即可，`CITYKEY` 是可选的老路子 |
| 玉林能不能查 | **能**。玉林市 `450900`，25 条线路 / 50 个方向，实时车辆正常 |
| 县市覆盖 | 北流 `450981`（3 线）、容县 `450921`（16 线）有独立城市码；陆川、福绵无独立码、经 `450900` 可达。**实测 48/48 个县级方向全部有实时**（§8.6） |
| 博白 / 兴业 | **确实没有**。三个目录（`450900`/`450981`/`450921`）里都搜不到线路，`450923`/`450924` 也都是 `-2` |
| 玉林全域线路总量 | **44 条**（`450900` 25 + `450981` 3 + `450921` 16），去重后 43 条（`北流105路` 重复） |
| 发车时刻表 | **可用**。`207` 按 `10:00`/`16:00` 分组给班次，`status` 语义已钉死：`1` 已发车 / `2` **下一班** / `3` 未发车；`116` 是简版（`●` = 下一班） |
| 唯一硬门槛 | 请求头必须带 **`Origin: https://h5.mygolbs.com`**。少了它所有命令都返回同一个 47 字符闸门块 |
| 主要阻塞项 | 无 |
| 授权风险 | 高。这是**私有客户端接口**，不是公开 API。低频个人查询可用；对外发布或商用必须先取得公交公司/服务商授权 |

**立项建议**：值得做，且成本极低。但应定位为"个人出行辅助的补充数据面"，与现有的车来了数据面并行、互为校验，
不要单独作为面向公众的生产数据源。

## 2. 立项背景与目标

### 2.1 背景

现有面板 `yulin-bus-activity` 只有一条数据链：车来了 H5（`web.chelaile.net.cn/api/`，玉林 `cityId=440`）。
单数据源的已知问题：

- 车来了玉林侧线路集是 23 条 / 46 个方向，**漏掉掌上公交侧的线路**（见 §8.2 差异清单）；
- 车来了实时车辆必须带渠道参数 `src=wechat_yulingongjiao`，渠道参数一旦失效，全城线路会安静地退化为
  「等待发车 / 无车」——故障形态和"真的没车"无法区分；
- 车来了返回的 `licence` 是**内部自编号**，不是车牌，与公交公司口径对不上（这也是本仓库
  `plate_map.json` 存在的原因）。

### 2.2 目标

1. 打通掌上公交 H5 数据面，作为玉林实时的**第二条独立数据链**；
2. 拿到**车牌口径**的车辆标识，与车来了的自编号口径互相校验；
3. 覆盖到玉林下辖县市（北流、容县），让面板不再局限于市区；
4. 明确该数据面的稳定性边界与授权边界，供后续决策。

### 2.3 范围外（本次不做）

- 不下 APK、不做抓包、不做 Frida hook（`CITYCODE` 已通，不需要）；
- 不改动现有 Go 主程序与面板（本报告只交付文档，不含代码改动）；
- 不评估微信小程序/公众号侧的数据面（未验证，见 §11）。

## 3. 数据面分类与授权边界

按"官方公开 API / 合作方 API / 私有客户端 API / 第三方开放数据"四类划分，本接口属于：

> **私有客户端 API**（第 3 类）。
> 它是掌上公交自家 H5 页面调用的后端，**能被调用不等于它是公开或受支持的产品**。

这意味着：

- 没有文档、没有版本承诺、没有 SLA，字段和参数随时可变（本报告已记录两处**已经失效**的旧结论，见 §9.4）；
- 没有公开的申请入口。我们要么用私有接口，要么走商务合作；
- 覆盖城市由掌上公交与各地公交公司的数据合作决定，**不是技术问题**。查不到数据的县（博白、兴业、福绵）
  是因为平台侧没接，不是因为我们的调用方式不对。**但注意有些县查不到只是因为没有独立城市码，
  它的车队挂在上级地级市下面（陆川即如此，见 §8.4）——所以"查不到"之前必须先去上级城市目录里搜一遍。**

分类依据：接口域名（`h5.mygolbs.com`）、调用方式（H5 bundle 内联的 `$.ajax`）、以及官方站点
`www.mygolbs.com` / `m.mygolbs.com` 上**没有任何开发者、开放平台或 API 文档入口**（已检索官方域，
未找到 developer/open-platform/API/data-service 相关页面——即"在已查来源中未找到公开文档"，
不等于官方一定没有）。

## 4. 接入规范

### 4.1 端点

| 项 | 值 |
|---|---|
| 方法 | `POST` |
| URL | `https://h5.mygolbs.com/ApiData.do` |
| Content-Type | `application/x-www-form-urlencoded` |
| 请求体 | 表单键值对，命令名放在 `CMD` 字段 |
| 响应 | `application/json`，**明文**，UTF-8 |
| 鉴权 | 无 |
| 限流 | 服务端未声明。本项目约定 **≥2s 间隔**，不要并发 |

同域还有一个「城市线路列表」页面 `https://h5.mygolbs.com/linelist.html?key=<CITYKEY>`，
它是老式的城市入口（见 §4.3）。

### 4.2 请求头（**这一节是接入成功的关键**）

| 头 | 值 | 必需 |
|---|---|---|
| `Origin` | `https://h5.mygolbs.com` | **必需** |
| `Referer` | `https://h5.mygolbs.com/` | 必需 |
| `User-Agent` | 任意常见移动端浏览器 UA | 必需 |
| `Content-Type` | `application/x-www-form-urlencoded` | 必需 |

**`Origin` 缺失的后果（实测）**：所有命令——包括原本不需要城市凭据的 `CMD=101`——都返回同一个 47 字符
base64 块：

```
0vx0czK73ykwCHaLBTiKh0iCXQINzRvSZw4+b/H8FgE52U=
```

HTTP 状态仍是 **200**。这个块对**任意参数组合逐字节相同**。

> **识别规则**：一个对差异极大的参数给出完全相同响应的接口，是**请求被闸门挡住**的特征，
> 不是"这座城市没数据"。本项目此前的错误结论——「空 `CITYKEY` 就没数据」——正是这个坑
> （真正的缺项是 `Origin`，不是 `CITYKEY`）。

### 4.3 城市选择器：优先 `CITYCODE`

三个字段都叫"城市"，优先级和语义完全不同：

| 字段 | 语义 | 性质 | 建议 |
|---|---|---|---|
| `CITYCODE` | 行政区划代码（玉林市 `450900`） | 公开、稳定、**永不轮换** | **首选** |
| `CITYNAME` | 城市名标签（`玉林市`） | 仅作标签，**必须非空**，不参与路由 | 必填，可随便填 |
| `CITYKEY` | 服务商为每个城市签发的私有凭据（`qz595803`） | 不公开、会轮换 | 不用 |

**实测确认**：

- `CITYCODE` 被 `119 / 103 / 104 / 106 / 110 / 114 / 115` 接受，**不需要任何城市凭据**，
  也不需要城市入口 URL。
- **路由由 `CITYCODE` 决定**：`CITYNAME=玉林市&CITYCODE=450981` 返回的是**北流**数据
  （3 条线），`CITYNAME=北流市&CITYCODE=450900` 返回的是**玉林**数据（25 条线）。别信 `CITYNAME`。
- `CITYNAME` 为空 → `{"status":"-2","msg":"当前城市暂无法提供公交查询"}`。
- `CITYCODE` 为空但 `CITYNAME` 填对 → 仍返回数据（说明有名称兜底），但**不要依赖**。

**不要再去挖 `CITYKEY`**，原因见 §9.4。它是老路子，且已经腐烂。

### 4.4 通用调用约定

- 命令名在 `CMD`，两位或三位数字字符串（`"104"`，不是数字 `104`）。
- 请求参数名**大小写敏感**，全大写：`CITYNAME`、`CITYCODE`、`LINENAME`、`DIRECTION`、`STATIONORDER`、`KEYWORD`。
- `LINENAME` 必须与 `CMD=119` 返回的 `lineName` **逐字节相同**（含中文括号）。
  错了不是空结果，而是 **HTTP 500**（见 §5.2）。
- `DIRECTION` 为 `"1"` / `"2"`，与 `119` 的 `upperOrDown` 对应。其他值 → **HTTP 500**。
- 1024 字节级的小响应，无分页，无 cursor。

## 5. 通用响应约定

### 5.1 状态码

**HTTP 层与业务层必须分开判断**——本接口两者不一致，这是最容易写错的地方。

| 层 | 值 | 含义 | 处理 |
|---|---|---|---|
| HTTP | 200 | 请求到达并返回（**不代表有数据**） | 继续看业务 `status` |
| HTTP | 500 | Tomcat 错误页（HTML，不是 JSON） | 参数非法，见 §5.2 |
| 业务 | `1`（数字） | 成功 | 读 `data` / `buslines` / `busstations` / `list`。**成功不代表有数据**（可能是空数组），`104` 实测 `msg` 为 `获取实时数据成功!` |
| 业务 | `0`（数字） | 失败，读 `msg` | 按 `msg` 处理 |
| 业务 | `-1`（**字符串**） | 无数据信息（线路名不存在） | 视为"该线路不在本城"，**不是错误** |
| 业务 | `-2`（**字符串**） | 该城市未接入 | 是平台侧结论，不要重试 |

`status` 的**类型不稳定**：成功时是数字 `1`，`-1` / `-2` 时是**字符串**。解析时请统一转字符串比较。

### 5.2 HTTP 500 的两种触发条件（实测）

| 触发 | 响应 |
|---|---|
| `LINENAME` 不存在（`CMD=103`） | HTTP **200**，`{"status":"-1","msg":"暂无数据信息！"}` |
| `LINENAME` 不存在（`CMD=104`） | HTTP **500**，HTML 错误页 |
| `DIRECTION` 非法（`CMD=103`，传 `"9"`） | HTTP **500**，HTML 错误页 |

也就是说：**同一个"线路名不对"，`103` 与 `104` 的表现不同**。客户端必须同时处理：
① 业务 `status=-1`；② HTTP 500 + `Content-Type: text/html`。
把 500 当成"没车"显示给用户是错的——它是"我们调错了"。

### 5.3 声明的容器字段与真实数据位置

每个命令的数据不在同一个键里，**没有统一的 `data`**：

| CMD | 数据所在键 |
|---|---|
| 101 | `data[]` |
| 106 | `data[]` |
| 110 | **`busstations[]`**（不是 `data`） |
| 115 | `data[]` |
| 119 / 102 / 114 | `buslines[]`（`busstations[]` 实测恒为空数组） |
| 103 | `data[]`（站序），另有顶层 `nihelist[]`（拟合轨迹） |
| 104 | **`list[]` 才是车辆**；`data[]` 是逐站到站向量 |
| 207 / 116 | `list[]` |

## 7. 接口详规

以下所有示例均为 **2026-10-12 实测原始响应**（截断），城市 `玉林市 / 450900`。

### 7.1 `CMD=101` — 全国城市列表

**用途**：取平台已开通的城市名。**用于判断城市是否存在，不能用于判断有无数据**。

**请求**

| 参数 | 必需 | 说明 |
|---|---|---|
| `CMD` | ✅ | `101` |

不需要 `CITYCODE` / `CITYKEY` / `Origin` 以外的坐标参数。

**响应**

```json
{ "data": [ { "cityname": "贵阳市" }, { "cityname": "长春市" }, { "cityname": "桂平市" } ] }
```

**字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `data[].cityname` | string | 城市名，**只有这一个字段** |

**实测**：565 条。玉林市、北流市、容县在列；**陆川县、博白县、兴业县、福绵区不在列**。

> ⚠️ 这个列表**不能用来判覆盖，两个方向都不行**：
> - 在列 ≠ 有数据（北流在列且有数据，但覆盖面仍以 `CMD=119` 的实际返回为准，见 §8）；
> - **不在列 ≠ 没数据**——`陆川`不在列表里，`陆川1路` 却有实时（见 §8.4）。
>
> 只能拿它做城市名字典。

---

### 7.2 `CMD=205` — 校验 `CITYKEY` / 城市配置

**用途**：仅在使用 `CITYKEY` 老路线时需要。**使用 `CITYCODE` 的项目不需要它。**

**请求**

| 参数 | 必需 | 说明 |
|---|---|---|
| `CMD` | ✅ | `205` |
| `CITYKEY` | ✅ | 城市凭据 |

**成功响应**

```json
{
  "city": { "cityname": "泉州市", "nearStation": "1", "logo": "", "company": "", "showName": "泉州", "download": "0" },
  "status": 1, "msg": "success"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `city.cityname` | string | 城市全名（可用于反查 key 对不对） |
| `city.showName` | string | 简称，用于界面标题 |
| `city.nearStation` | string | `"1"`/`"0"`，是否提供周边站点能力 |
| `city.download` | string | `"1"`/`"0"`，是否展示 App 下载入口 |

**失败响应**

```json
{ "status": 0, "msg": "当前城市尚未开通web服务！" }
```

**实测有效的 `CITYKEY`**（仅作存证，**不建议使用**）：`qz595803` 泉州市、`fcg240723` 防城港市、`wuhai1206` 乌海市。

### 7.3 `CMD=119` — 线路目录

**用途**：**基础数据接口**。取一座城市的全部线路与方向。做新城市接入的第一步就是它。

**请求**

| 参数 | 必需 | 说明 |
|---|---|---|
| `CMD` | ✅ | `119` |
| `CITYNAME` | ✅ | 城市名标签，非空 |
| `CITYCODE` | ✅（推荐） | 行政区划码，决定路由 |
| `KEY` | ➖ | 线路关键字过滤，空串 = 全部 |

**响应**

```json
{
  "buslines": [
    {
      "number": "", "cityName": "", "lineName": "1路",
      "beginTime": "", "endTime": "", "upperOrDown": "1",
      "from": "玉林火车站", "to": "汽车总站（二医院）",
      "comments": "", "stationName": "", "stationID": "", "commentStationName": "",
      "neartext": "", "nexttext": "", "nearnum": 0, "neardis": "", "neartime": "",
      "distance": "", "routeNameUp": "", "routeNameDown": "",
      "shortName": "", "stationOrder": "", "company": ""
    }
  ],
  "busstations": [], "status": 1, "msg": "success"
}
```

**字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `buslines[].lineName` | string | **线路名**，`103/104` 的 `LINENAME` 必须与它逐字节一致 |
| `buslines[].upperOrDown` | string | 方向：`"1"` 上行 / `"2"` 下行 → `DIRECTION` |
| `buslines[].from` / `.to` | string | 起讫站名 |
| `buslines[].routeNameUp` / `.routeNameDown` | string | 变体方向的展示名（实测常为空） |
| `buslines[].comments` | string | 备注（实测常为空，票价在 `103` 的 `commonts`） |
| `buslines[].company` | string | 运营公司（实测常为空） |
| `busstations` | array | 实测恒为空 `[]` |

**要点**

- **一个 `lineName` 会出现两次**（上行 + 下行），按 `(lineName, upperOrDown)` 才是唯一键。
- `119` 默认返回全部；`KEY` 是**包含匹配**，实测 `KEY=北流` 得到 6 个方向（含
  `玉林至北流城际公交线路`）；`KEY` 无匹配时返回 `{"buslines": [], "status": 1, "msg": "success"}`
  ——**空数组不是错误**。
- `beginTime` / `endTime` 在这里常为空，首末班请以 `103` 的 `firstLast` 为准。
- 玉林市 `450900` 的 25 条线**包含跨县线路**（`陆川1路`、`北流105路`、`玉林至北流城际公交线路`），
  它们同时也会出现在对应县市的目录里 → **跨城市码去重是客户端的事**（见 §9.3）。

### 7.4 `CMD=102` / `CMD=114` — 线路搜索

### 7.5 `CMD=103` — 线路站序、首末班、票价

**用途**：**核心基础接口**。取一条线路一个方向的完整站序、首末班、票价、运营公司、轨迹点。

**请求**

| 参数 | 必需 | 说明 |
|---|---|---|
| `CMD` | ✅ | `103` |
| `CITYNAME` | ✅ | 城市名标签 |
| `CITYCODE` | ✅（推荐） | 行政区划码 |
| `LINENAME` | ✅ | 线路名，必须与 `119` 的 `lineName` 完全一致 |
| `DIRECTION` | ✅ | `"1"` / `"2"`，其他值 → HTTP 500 |
| ~~`ROUTEID`~~ | ❌ | **`103` 不认 `routeId`**：只给 `ROUTEID=1011`（带 `CITYNAME`）→ `{"status":"-1","msg":"获取线路数据失败！"}`（2026-10-12 复测）；把 `CITYNAME` 也去掉 → HTTP 500。按 `routeId` 寻址是 `207`/`116` 的事 |

**响应（实测 `1路` 方向 1）**

```json
{
  "routeName": "1路", "upperOrDown": "1",
  "beginTime": "06:03", "endTime": "22:20", "planTime": "", "routeColor": "",
  "commonts": "票价：2元/人次",
  "routeId": 1, "loopType": "1", "showDepart": 1, "routeName2": "",
  "telephoneTips": "咨询电话",
  "firstLast": [ { "first": "06:30", "last": "20:25" } ],
  "companys": [],
  "data": [
    {
      "stationId": 0, "stationName": "玉林火车站",
      "station_lon": 110.15834768, "station_lat": 22.59757448,
      "stationOrder": 1, "showName": "玉林火车站",
      "come": 0, "arrive": 0, "stationsStatus": 1, "StationNihePointIndex": 0
    }
  ],
  "nihelist": [ { "lat": "22.721701", "lng": "110.248008" } ],
  "status": 1, "msg": "success"
}
```

**顶层字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `routeId` | number | **线路 ID**，`207` / `116` 的入参（实测 `1路`=1、`G01路`=701、`北流105路`=40105） |
| `beginTime` / `endTime` | string | 首末班（**字符串**，`HH:MM`；`1路` 为 `06:03` / `22:20`） |
| `firstLast` | array | `[{first, last}]`，**页面上显示的首末班以它为准**（`1路` 为 `06:30`/`20:25`） |
| `commonts` | string | **注意拼写是 `commonts`**（不是 `comments`）。票价 / 备注文字 |
| `showDepart` | number | `1` = 该线路提供发车时刻表（可调 `207`） |
| `loopType` | string | `"1"` 环线标记（实测多条线路均为 `"1"`，语义未进一步确认） |
| `routeName2` | string | 副名，实测为空 |
| `telephoneTips` | string | 咨询电话提示文字，实测 `"咨询电话"` |
| `companys` | array | 运营公司，实测为空 `[]` |
| `nihelist` | array | **拟合轨迹点**（`{lat, lng}` 字符串坐标），用于地图画线。`G01路` 实测 558 点 |

**站序字段（`data[]`）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `stationName` | string | 站名（显示 / 匹配用真名，不要用 `showName` 做跨方向匹配） |
| `showName` | string | 展示名（实测与 `stationName` 相同） |
| `station_lat` / `station_lon` | number | **真实坐标**，`115` 必须用这两个值 |
| `stationOrder` | number | **站序，从 1 开始**（`data[0].stationOrder == 1`） |
| `Come` / `arrive` | number | `0/1`，到站 / 进站标记（静态查询下为 0） |
| `stationsStatus` | number | 站点状态标记 |
| `StationNihePointIndex` | number | 该站在 `nihelist` 中的起始下标 |
| `stationId` | number | **实测恒为 0**，不可用，见 §9.3 |

**要点**

- 站序数组**已按 `stationOrder` 升序**，可直接用。
- `beginTime/endTime` 与 `firstLast` 会不一致（`1路` 顶层 `06:03/22:20` vs `firstLast` `06:30/20:25`）。
  **不要混用**：前者是运营时段，后者是发车时段。本仓库 README 里 9 路的"临时站"规则、
  以及"日班收班后切夜班"的判据，都应该基于**明确的一个口径**，建议统一取 `firstLast`。
- 线路名不存在 → HTTP **200** + `{"status":"-1","msg":"暂无数据信息！"}`。

|---|---|---|

| `stationIndex` | string | **目标站序号，0-based**（传 `STATIONORDER=10` → `"9"`；传 `3` → `"2"`） |
| `busNumber` | string | 提供该估计的车辆**车牌** |
| `busToStationCount` | number | 还有几站（**无车时为 `-1`**） |
| `busToStationTime` | number | 还有几分钟（浮点，无车时 `0.0`） |
| `busToStationDistance` | number | 还有多少米 |
| `busToStationTips` | string | 站数文案：`"4站"` / `"即将到站"` / **`"等待发车"`** |
| `busToStationTimeTips` | string | 时间文案：`"5分钟"` / `"小于1分钟"` / 空 |
| `busToStationDistanceTips` | string | 距离文案：`"1.6公里"` / `"230米"` |
| `busToStationName` | string | 参考站名（最近站） |
| `stationLat` / `stationLng` | string | 目标站坐标（**字符串**） |
| `planTime` / `routeNameUp` / `routeNameDown` | string | 实测为空 |

**语义与实测行为**

- **一条记录 = 一辆正在接近目标站的车。** 目标站是终点时可能有多条记录（实例：传 `STATIONORDER=14`
  得 2 条，分别是"还有 1 站 / 即将到站"和"还有 8 站"的两辆车）。
- **`busToStationCount = -1` + `busToStationTips = "等待发车"`** 表示**当前没有车在接近**该站
  （该方向首班未发或已收班）。这不是接口错误，**不要当成"数据获取失败"**。
- **`STATIONORDER` 超出站数**（如 `1路` 只有 14 站却传 `99`）→ `routeOnStationRTimeInfoList` 为空数组，其余字段照常。
- `STATIONORDER` 对 `list` / `data` / `dislist` / `speedlist` **无影响**（实测 `None` / `"1"` / `"10"` / `"14"`
  四次调用这几个数组完全一致）。**它只影响 `routeOnStationRTimeInfoList`。**
- 与本仓库面板的 `targetOrder` 模型**高度契合**：`GET /lines/{lineId}/realtime?targetOrder=N` 可直接映射到
  `CMD=104` + `STATIONORDER=N`，`busToStationCount` / `busToStationTimeTips` 即"还有 N 站 / 几分钟"。

### 7.8 `CMD=115` — 站点经停线路

**用途**：取某个站点有哪些线路经停，以及在该站的方向与站序。

**请求**

| 参数 | 必需 | 说明 |
|---|---|---|
| `CMD` | ✅ | `115` |
| `CITYNAME` | ✅ | 城市名标签 |
| `CITYCODE` | ✅（推荐） | 行政区划码 |
| `STATIONNAME` | ✅ | 站名 |
| `MYLAT` / `MYLNG` | ✅ | **必须是该站的真实坐标**（取自 `103` 的 `station_lat/station_lon`） |
| `ALL` | ➖ | `"1"` 返回两个方向，`"0"` 只返回同向 |

**响应（实测 `玉林火车站`，`ALL=1`，9 条）**

```json
{
  "data": [
    { "lineName": "1路", "upperOrDown": "2", "from": "", "to": "玉林火车站", "number": "", "cityName": "" }
  ],
  "type": 0, "status": 1, "msg": "success"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `data[].lineName` | string | 线路名 |
| `data[].upperOrDown` | string | 在该站的**方向**（与 `119` 口径一致）→ 可直接喂 `104` |
| `data[].stationOrder` | number | 该站在这条线该方向上的站序（`getLineByStationV2` 用它跳转） |
| `data[].routeBean` | object | 部分记录带（实测「宁屋角」的结果里有 `routeBean.id`） |
| `type` | number | 实测恒为 `0`，语义未确认 |

**⚠️ 必读：`MYLAT`/`MYLNG` 传错会静默返回空**

实测同名站点，坐标不同结果完全不同：

| `STATIONNAME` | `MYLAT/MYLNG` | `ALL=1` | `ALL=0` |
|---|---|---|---|
| `玉林火车站` | `22.59757448, 110.15834768`（**取自 `103`**） | 9 条 | 4 条 |
| `玉林火车站` | `22.6036, 110.1578`（随手填的近似值） | **0 条** | **0 条** |
| `金城商厦（市中医院）` | `22.63123544, 110.15571153`（**取自 `103`**） | 7 条 | 4 条 |
| `金城商厦（市中医院）` | `22.6293, 110.1482`（随手填的近似值） | **0 条** | **0 条** |

空结果是 `{"data": [], "type": 0, "status": 1, "msg": "success"}` ——**业务状态仍然是成功**。
这是一个典型的"静默失败"：**必须先用 `103` 取真实坐标，不要用 `106` 的坐标或估算值**。

| `list[].group` | string | 时间段标题，直接可显示。实测分段点是 `10:00` / `16:00`（`陆川1路` 3 组；`1路` 另多一组，说明还可能按线路再切，**不要假设固定 3 组**） |
| `list[].times[].time` | string | 发车时刻 `HH:MM`，组内**升序** |
| `list[].times[].status` | number | **实测语义已钉死**：`1` = 已发车、`2` = **下一班**、`3` = 未发车 |
| `list[].times[].notes` / `noteText` | string | 备注（实测为空） |
| `list[].times[].isDelete` | number | `0` 有效 |

**`status` 语义的判定依据（两条独立证据）**

1. 本地时间 08:07 时，`陆川1路` 组 1 为 `…08:00=1, 08:30=2, 08:50=3…`；
   `1路` 组 1 为 `…07:56=1, 08:08=2, 08:11=3…`。两线各自的 `2` 都是 **now 之后的第一个时刻**，
   且 `now` 之前的全是 `1`、之后的都是 `3`。
2. `CMD=116` 给同一份时刻表加 `●` 时，**`●` 恰好落在 `status=2` 的那一个时刻上**（见 §7.11），
   两条命令互相印证。

**要点**

- 入参用 `ROUTEID`（数字线路 ID），**不是线路名**。一个 `routeId` 覆盖两个方向，必须配 `DIRECTION` 才唯一。
- `CITYKEY` 可以省略。`CITYCODE` 有效：`CITYCODE=450900` 通；只给 `CITYNAME=陆川县`（无 `CITYCODE`）→
  `{"status":"-2","msg":"当前城市暂无法提供公交查询"}`（陆川不是城市名）。
- **失败是静默的**：`ROUTEID=999999` 与 `DIRECTION=9` 都返回 `{"list": [], "status": 1}`。
  **注意 `207` 的非法 `DIRECTION` 不会像 `103`/`104` 那样给 HTTP 500**，判断依据只能是空 `list`。
- ⚠️ **时刻表可能不是全天完整班表**：实测 `陆川1路` 方向 1 的 `103.firstLast` 写 `06:00/21:00`，
  但 `207` 只给到 `17:30` 收尾。**不要用 `207` 的末组时间当作收班时间**，两者口径不同。

### 7.11 `CMD=116` — 发车时刻（简版，带实时标记）

**用途**：与 `207` 同源，输出更简，且标记了"当前时段"与"下一班"。

**请求**：`CMD=116` + `CITYNAME`（或 `CITYCODE`）+ `ROUTEID` + `DIRECTION`（同 `207`）

**响应（实测 `陆川1路` `routeId=1011` 方向 1，本地 08:07）**

```json
{
  "list": [
    { "group": "06:37~10:00", "times": ["06:37","07:10","07:26","08:00","08:30●","08:50","09:10","09:38"], "isNow": 1 },
    { "group": "10:00~16:00", "times": ["10:10","10:30","..."], "isNow": 0 },
    { "group": "16:00~17:30", "times": ["16:00","16:20","..."], "isNow": 0 }
  ],
  "status": 1
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `times[]` | string[] | 时刻字符串。**`●` 后缀标记的是「下一班」**，恰好等于 `207` 里 `status=2` 的那一个时刻 |
| `isNow` | number | `1` = 当前所处的时段（08:07 → 组 1 `06:37~10:00`，实测 `[1,0,0]`） |

**要点**

> ⚠️ **`●` 不是"已发车"标记。** 实测 08:07 时，`08:30` 带 `●`（未来 23 分钟）；
> `1路` 同一时刻 `08:08` 带 `●`（未来 1 分钟）。两线都证实 `●` = **now 之后的第一班**，
> 与 `207` 的 `status=2` 一一对应。按"已发车"渲染会把还没走的那班画成已走。

- 想要"还有几分钟"不要用 `116` 自己算：用 `207` 的 `status=2` 定位下一班，
  再和 `104` 的 `routeOnStationRTimeInfoList`（实测分钟数）交叉。
- 与 `207` 一样，本命令的班表也可能不是全天完整的（见 §7.10 末条）。

### 8.3 跨城市码重叠（去重警告）

同一批车/线路会出现在多个 `CITYCODE` 的目录下，实测两类：

- **整条线重复**：`北流105路` 同时在 `450900`（玉林市）和 `450981`（北流市）目录里，

由于重复的是**同源数据**，去重只需选一个入口，不需要做字段级合并。

### 8.4 县级实时数据可以挂在上级地级市下面 ⚠️

**这是本次最容易踩的坑，也是 §8.1 那一列 `status:-2` 的正确读法。**

实测（2026-10-12 07:46 CST）：

| 项 | 值 |
|---|---|
| `CITYCODE=450922`（陆川县） | `{"status":"-2","msg":"当前城市暂无法提供公交查询"}` |
| `CMD=101` 城市列表 | **不含**陆川（列表里没有"陆川"字样） |
| 但 `CMD=119` `CITYCODE=450900` `KEY=陆川` | **有** `陆川1路`，2 个方向 |
| `CMD=103` `LINENAME=陆川1路` `DIRECTION=1` | `routeId=1011`，19 站，`firstLast=[{"first":"06:00","last":"21:00"}]`，`县瓷厂` ↔ `沙湖镇政府` |
| `CMD=104` 同线 `DIRECTION=1` | `hasReal=1`，1 辆 `桂K11819D`（07:46 在 `政务中心` → 07:47 已在 `县政协`） |

**三条推论**（都会影响接入设计）：

1. **城市码缺失 ≠ 无实时。** 判断一个县有没有数据，唯一可靠的办法是
   **在上级地级市目录里 grep 线路名**（`CMD=119` + `KEY=<县名>`），不要在 `450922` 上判死刑。
2. **`CMD=101` 的城市列表既不是"有实时"的充分条件，也不是必要条件。**
   北流在列表里且有数据；陆川**不在列表里**却有实时数据。
   这个列表只能用来做城市名字典，不能用来判覆盖。
3. **县级线路的 `company` 是上级公司**：`114` 实测 `陆川1路` 的 `routeBean.company = "玉林公交"`，
   `routeId = 1011`（不是陆川自己的编号段）。

**对本项目的直接影响**：只按"县市自己的城市码"拉目录，会漏掉**没有城市码的县级车队**（陆川就是）。
正确做法是**从地级市目录 `450900` 里搜线路名**来判覆盖，把县市当作**线路名的前缀标签**
（`陆川`、`北流`、`容县`）；有独立城市码的（北流 `450981`、容县 `450921`）再按需补拉，靠 `(lineName, from, to)` 去重（§8.3、§12.1）。

## 9. 字段语义与已知陷阱

### 9.1 `busNumber` 是车牌，不是自编号

- 掌上公交 `104.list[].busNumber` = **车牌号**（实测 `桂K08842D` / `桂KH5266` / `桂K08856D` / `桂KU9080`）。
- 车来了 `busList` 的 `licence` = **内部车队编号**（`433`、`435`…）。
- **两者是不同标识空间，不能直接 join。** 要做融合，必须借助本仓库已有的
  `plate_map.json`（车牌 ↔ 自编号映射）作为桥。
- 附带收益：掌上公交侧**直接提供车牌**，可用于交叉校验 `plate_map.json` 的正确性，
  以及验证 README 中"549–554 这 6 辆车的 `licence` 一直是车牌"的说法。

### 9.2 站序的两套编号，差 1

| 场景 | 编号 | 基准 | 实例 |
|---|---|---|---|
| `103.data[].stationOrder` | **1-based** | 第 1 站 = 1 | `1路` 首站 `玉林火车站` → `1` |
| `104.list[].index` | **0-based** | 第 1 站 = 0 | 停在 `禾力塘`（第 4 站）→ `index: 3` |
| `104.routeOnStationRTimeInfoList[].stationIndex` | **0-based，字符串** | 同上 | 传 `STATIONORDER=10` → `"9"` |
| `104` 请求参数 `STATIONORDER` | **1-based** | 与 `103` 同口径 | 传 `10` = 第 10 站 |

**`STATIONORDER` 用 `103` 的站序，`104` 回给你的下标要减 1 才能对上。** 这是本接口最容易算错的地方。

### 9.3 恒为空 / 恒为 0 的字段（不要用）

| 字段 | 出现位置 | 实测值 |
|---|---|---|
| `stationId` | `103.data[]` / `110.busstations[]` | 恒 `0` |
| `station_lat` / `station_lon` | `110.busstations[]` | 恒 `0.0` |
| `busstations` | `119` / `102` / `114` 顶层 | 恒 `[]` |
| `crowdStatus`、`personNumOnBus`、`busType`、`runType`、`sectionStation`、`busRaoXingTips`、`abnormal` | `104.list[]` | 恒空串 |
| `company` | `119.buslines[]` | 实测常为空（用 `114.routeBean.company` 代替） |
| `routeNameUp` / `routeNameDown`、`stationOrder`、`stationName`、`stationID` | `119.buslines[]` | 实测为空（线路级信息请走 `103`） |

`117` 依赖 `STATIONID`，而所有路径拿到的 `stationId` 都是 `0` → **`117` 在当前数据面下不可用**（见 §11）。

### 9.4 已经失效的两条历史结论（**不要再照着做**）

1. **「`CITYKEY` 必填，是接入的唯一阻塞」——已作废。**
   现在的门槛是请求头 `Origin`，不是 `CITYKEY`。用 `CITYCODE` 完全绕开了 `CITYKEY`。
2. **「某个 `CITYKEY` 表可以复用」——已作废，且会长久腐烂。**
   实测：wherebus 项目表里的 `nn771801`（南宁）与掌上公交自家 bundle 里的 `nanning920901`
   **今天都已失效**，而 `CITYCODE=450100` 正常工作。猜测格式同样无效：
   `yl775801`、`yl450900`、`bl775801`、`rx775801` 全部被拒。
   **`CITYKEY` 会轮换 → 任何硬编码 key 的表都是定时炸弹。**

### 9.5 类型与拼写陷阱汇总

| 陷阱 | 说明 |
|---|---|
| `status` 类型不稳定 | 成功是数字 `1`，`-1` / `-2` 是**字符串** |
| `103` 的票价字段拼写 | **`commonts`**（不是 `comments`） |
| `106` 的字段名 | `name` / `lat` / **`lon`**（不是 `stationName` / `lng`） |
| `106` / `routeOnStationRTimeInfoList` 的坐标 | **字符串**类型 |
| `110` 的容器键 | `busstations`，不是 `data` |
| `104` 的车辆数组 | **`list`**，不是 `data`（`data` 是逐站向量） |
| `firstLast` vs `beginTime/endTime` | 两套时间口径，不要混用 |
| 线路名必须逐字节一致 | 含中文全角括号，如 `金城商厦（市中医院）` |
| 覆盖判断 | **不能按线路名里的县名推城市码**：`陆川1路` 只在 `450900` 下，`450922` 报 `-2`（§8.4） |
| 容县线路的可见性 | 容县的 16 条线**只在** `450921` 下，`450900` 目录里一条都没有（`KEY=容县` 返回 0） |
| 双向站数不等 | `容县21路` 11/13 站、`玉林总站-福绵新滔工业园` 29/32 站。**别假设双向站表等长**，`STATIONORDER` 只对当前 `DIRECTION` 有效（§8.6） |
| `routeId` 不是连号 | 分区命名：市区 `1`/`G01=701`、专线城际 `131/141/151`、陆川 `1011`、北流 `401xx`、容县 `200xx`。**别按大小反推归属**（§8.6） |
| `207` 与 `116` 整分钟边界 | 采样跨过发车点时两者会差一班（`207` `08:14` vs `116` `08:26●`）。**要"下一班"就只取一条命令**（§8.5） |
| `116` 的 `●` | 标的是**下一班**（= `207.status==2`），**不是"已发车"**（§7.11） |
| `207`/`116` 的静默失败 | 假 `ROUTEID` / 非法 `DIRECTION` 都返回 `{"list":[],"status":1}`，**不给 HTTP 500**（与 `103`/`104` 不同）（§7.10） |
| 班表 vs 首末班 | `207` 的末组时间（`陆川1路` 到 `17:30`）**不等于** `103.firstLast` 的末班（`21:00`），别混用（§7.10） |

## 10. 与车来了侧对照（两套数据面）

| 维度 | 掌上公交 H5 | 车来了 H5 |
|---|---|---|
| 入口 | `POST https://h5.mygolbs.com/ApiData.do` | `https://web.chelaile.net.cn/api/` |
| 城市选择 | `CITYCODE`（行政区划码，稳定） | `cityId`（玉林 `440`） |
| 加密 / 签名 | **无** | AES-256-ECB + MD5 签名 |
| 城市/渠道参数 | 无 | **必须带 `s=h5`；实时必须带 `src`** |
| 响应包裹 | 明文 JSON | `**YGKJ{...}YGKJ##`，取 `.jsonr` |
| 车辆标识 | `busNumber` = **车牌** | `licence` = **自编号** |
| 玉林线路数 | **44 条**（`450900` 25 + `450981` 3 + `450921` 16）/ 88 向 | 23 线 / 46 向 |
| 县市覆盖 | 北流市、容县**独立城市码**；陆川等县线路**并入玉林市目录**（§8.4） | 玉林单城（`cityId=440`） |
| 到站估计 | `104` + `STATIONORDER` → 站数/分钟/距离 + 文案 | `busList.action` 自带 |
| 发车时刻表 | `207` / `116` | 未在本项目使用 |
| 故障形态 | 缺 `Origin` → 固定 47 字符块（易识别） | 缺 `src` → 全城"等待发车"（**难识别**） |

**对项目最有价值的三点**：

1. **校验能力**：掌上公交的车牌口径可以直接校验车来了的自编号口径（`plate_map.json`）；
2. **覆盖增量**：补上车来了侧没有的专线、城际线和 `G01路`，并给出北流、容县，以及**陆川**（`陆川1路` 有实时，见 §8.4）的县级数据；
3. **故障可辨识**：缺参数的表现是"固定的错误响应"，而不是"安静地变成没车"。

**注意**：两套数据面**不要混用同一个 `lineId`**。掌上公交用 `(lineName, direction)` 寻址，
车来了用不透明 ID；同一个线路名的两条数据来自不同的上游厂商，站序/首末班可能不一致
（本仓库 README 已记录的 9 路"临时站"、23 路"中途折返"都属于运营规则差异，不属于接口差异）。

## 12. 客户端实现建议

按最小改动、够用即止的原则：

### 12.1 线路目录：拉一次，缓存

`CMD=119` 是唯一的"目录"来源，且响应小（玉林 25 线约几 KB）。**按城市启动时拉一次、落盘缓存**，
不要每次请求都调。刷新周期建议 ≥ 1 天（线路变化很低频）。

**目录要拉几个城市码取决于要覆盖谁**（实测口径，见 §8.6）：

| 要覆盖 | 拉这些 `CITYCODE` | 目录结果 |
|---|---|---|
| 全部玉林（含全部县级线路） | `450900` + `450981` + `450921` | 25 + 3 + 16 = **44 条线**（去重后 43，`北流105路` 重复） |
| 只要市区 + 县级线（含陆川、福绵） | `450900` | 25 条线 |
| 只要容县 | `450921` | 16 条线 |

三个码**必须都拉**才叫"全覆盖"：`450900` 里没有容县的 16 条线，`450981`/`450921` 里没有陆川和福绵的线。
拉完之后**必须按 `(lineName, from, to)` 去重**（§8.3）；重复的是同源数据，选一个入口即可。
**博白、兴业没有任何入口**（§8.1）。

### 12.2 线路寻址：显式带上 `(lineName, direction, citycode)`

上游用"名字 + 方向"寻址，没有线路 ID 作为主键（`routeId` 只在 `207`/`116` 用）。
本地模型建议：

```
LineKey = citycode + ":" + lineName + ":" + direction     // 例 "450900:1路:1"
```

这与 `wherebus` 的 `"<lineName>:<direction>"` 约定同构，便于日后再接第三个数据面。

**不要**用 `lineName` 单独作键——同一个名字有两个方向；也不要跨城市合并。

⚠️ **`citycode` 存的是"调用时要用哪个城市码"，不是地理归属。** `陆川1路` 必须用 `450900` 调，
用 `450922` 会得到 `status:-2`（§8.4）。所以这个值只能从 `119` 的目录来源带着走，
**不要**按线路名里的县名反推城市码。

### 12.3 实时轮询：一次请求就够

用户看一条线路时，**只需要一个请求**：

```
CMD=104 + CITYNAME + CITYCODE + LINENAME + DIRECTION + STATIONORDER=<目标站站序>
```

`list` 给车辆与坐标（画轨迹用 `nihePointIndex` + `103.nihelist`），
`routeOnStationRTimeInfoList` 给"还有几站 / 几分钟 / 多远"。
不需要再调别的东西。轮询间隔建议与现有面板一致（10s 级）。

### 12.4 错误处理（必须实现）

| 情况 | 判据 | 正确做法 |
|---|---|---|
| 请求被闸门挡 | HTTP 200 + 47 字符 base64 块 | 检查 `Origin` / `Referer` 头，**不要显示"没车"** |
| 城市未接入 | `status == "-2"` | 提示"该地区暂无数据"，不重试 |
| 线路名不对 | `status == "-1"` 或 HTTP 500 | 提示内部错误，重拉 `119` 对账 |
| 该站无车接近 | `busToStationCount == -1` / `busToStationTips == "等待发车"` | 正常展示"等待发车"，**不是错误** |
| 上游超时 / 5xx | — | **必须返回明确错误，不要返回空数组假装"没车"** |

最后一条与本仓库 README 已声明的原则一致（"上游出错时返回 502 和明确错误，**不返回空数组假装『没车』**"）。

### 12.5 建议的最小接口面

只做**四件事**就能覆盖面板需求：

| 需求 | 用 |
|---|---|
| 线路列表 | `CMD=119`（缓存） |
| 线路详情（站表 / 走向 / 首末班 / 票价） | `CMD=103`（+ `nihelist` 画走向） |
| 实时车辆 + ETA | `CMD=104` + `STATIONORDER` |
| 站点搜索 / 周边 | `CMD=110`、`CMD=106`，站点线路用 `CMD=115` |

实施顺序：先 `103`（站表，出 `stationOrder`/`routeId`/`firstLast`），再 `104`（实时车 + ETA）。
`207`/`116` 只在产品明确要"下一班几点发车"时才加——`status=2` / `●` 就是下一班。

### 12.6 落地情况（2026-10-12，`北流105路` / `陆川1路`）

本仓已按本节接入两条县市线路（`北流105路`、`陆川1路`，共 4 个方向）：`internal/mygolbs`（客户端）
+ `internal/server`（按 `mg` 前缀分派，`/lines` 与车来了目录合并）。与上面的建议有几处**没照做**，
都是落地时实测后改的，记在这里免得后人以为漏了：

- **没有用 `CMD=119` 当目录。** 只接几条线时按名字寻址更省事也更稳：线路表写在 Go 里
  （`catalog`：`CITYCODE` + `CITYNAME` + 线路名 + 方向），站表/首末班/票价一律从 `103` 现取并缓存 1 小时。
  要接的线路多起来再换回 `119` 拉目录。
- **寻址方式按命令分**：`103`/`104` 只认 `LINENAME`（给 `ROUTEID` → `-1`），`207`/`116` 只认 `ROUTEID`。
  `CITYNAME` 哪个命令都不能省（缺了给 `ROUTEID` 会 HTTP 500）。见 §7.5。
- **`陆川1路` 挂 `450900`**：陆川没有自己的城市码（`450922` → `-2`），所以 `catalog` 里城市码写 `450900`、
  城市名写 `玉林市`，线路名仍按 `119` 目录里的原样（`陆川1路`）。（§8.4）
- **`nihelist` 没用上。** 面板的走向条只按「站序 + 站间比例」画，不需要折线（地图那套早删了），
  `103` 里那 300~400 个点白拿不用。
- **每站最多 2 条预测**（§9.5 已记）：实施时按「有预测就透出、没有就给 0」处理，界面显示「无预测」，
  **不要**用 `busToStationCount > 0` 反推一个分钟数——那是编的。
- **`busNumber` 是车牌**，所以不过车牌映射表，也不标「未知车牌」；`confidence` 恒 `high`。
- 抓包存在 `internal/mygolbs/testdata/`（2026-10-12 08:30 CST），单测按它断字段映射。

## 13. 风险与合规

| 风险 | 等级 | 说明与对策 |
|---|---|---|
| **未授权使用** | 高 | 私有客户端 API，无公开文档与授权。**对外发布/商用前必须取得运营方（掌上公交 / 玉林市公共汽车公司）授权**。个人出行辅助查询是当前的默认定位 |
| 接口随时变更 | 中 | 无版本承诺。对策：把 §9.4 的"会腐烂"部分写进代码注释；不要硬编码 `CITYKEY`；对 `status` 新增值做宽容处理 |
| 静默失败 | 中 | `115` 坐标不符、`117` 无 ID 都返回"成功 + 空数据"。对策：把 §8 / §9 的判据写成断言或日志 |
| 上游限流 / 封 IP | 中 | 服务端未声明限流。对策：保持 ≥2s 间隔，不并发，做本地缓存；参照本仓库对车来了侧的做法 |
| 数据准确性 | 中 | 车载设备老化（见 README：玉林调度一体机约 2018 年装），`_recTime` 会比请求时刻晚 1–2 分钟。**不要把 ETA 当准点表** |
| 双源不一致 | 低 | 两套数据面上游厂商不同，站序/首末班可能不一致。对策：不 merge，做展示侧对照 |
